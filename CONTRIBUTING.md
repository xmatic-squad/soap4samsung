# Участие в Soap4Samsung

Можно открывать issues, обсуждать ошибки и предлагать изменения через pull requests
в [xmatic-squad/soap4samsung](https://github.com/xmatic-squad/soap4samsung).
Проект сохраняет простой интерфейс для пульта и небольшой расход ресурсов
старых Samsung TV. Перед крупной функцией полезно описать сценарий в issue,
чтобы согласовать его с этим направлением.

## Сообщить о проблеме

Укажите версию приложения, модель ТВ, версию Tizen/прошивки, шаги воспроизведения,
ожидаемый результат и фактическую ошибку. Для сбоя видео полезны название материала,
показанное разрешение, время до сбоя и нажатые кнопки. Полная ссылка потока не нужна.

Не публикуйте логин/пароль, токены, cookies, DUID, сертификаты, архивы подписи,
полные ответы входа или скриншоты с полями аккаунта. Сетевые дампы могут содержать
данные доступа даже тогда, когда пароль в них не виден. Для примера ответа API
используйте минимальный синтетический объект с вымышленными значениями.

Если обнаружили утечку секрета, не копируйте секрет в публичный issue или PR.
Сообщите о проблеме владельцам проекта без значения секрета и отзовите доступ,
если он относится к вашему аккаунту.

## Предложить изменение

1. Сделайте fork репозитория в GitHub и склонируйте **свой fork**.
2. Создайте отдельную ветку, например `git switch -c fix/player-focus`.
3. Внесите изменение, сохраняя правила [AGENTS.md](AGENTS.md).
4. Выполните `npm test` и `npm run build`. Проверки не требуют аккаунта сервиса.
5. Для изменений интерфейса проверьте preview, для изменений плеера по возможности
   также свой ТВ. Подпишите пакет своими сертификатами и войдите на своём устройстве.
6. Просмотрите diff, убедитесь, что в нём нет личных данных и сборочных артефактов,
   отправьте ветку в свой fork и откройте PR в `main` этого проекта.

Установка и разработка описаны в [README](README.md) и
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Зависимости приложения не устанавливаются
через npm: проект использует обычный JavaScript и системный AVPlay.

В описании PR объясните проблему и получившееся поведение, перечислите проверки
и их ограничения. Если на ТВ не проверяли, отметьте это прямо. Для исправления
гонки нужен тест её поведения, а для простой правки текста отдельный тест не нужен.
Не включайте независимые переписывания и изменения пользовательских данных ради теста.

## Кто принимает изменения

Публичные issues и PR доступны всем участникам. Обязательное одобрение изменений
и их слияние остаются за поддерживающими проект владельцами кода из
[CODEOWNERS](.github/CODEOWNERS). Отзывы остальных участников полезны,
но не заменяют обязательное одобрение владельца кода.
Для собственных обновлений у мейнтейнера есть исключение из требования PR;
обязательные проверки сборки сохраняются. Это не предоставляет прав внешним
участникам.

Настройки защищённой ветки и проверки GitHub применяются на стороне репозитория;
изменение текстового файла само по себе не даёт участнику права слияния.
Изменения CODEOWNERS и автоматизации также проходят проверку владельцев проекта.
Для PR из fork не нужны ключи подписи, аккаунты Soap4me/Samsung или секреты CI.

Исходный код распространяется по [лицензии MIT](LICENSE).
