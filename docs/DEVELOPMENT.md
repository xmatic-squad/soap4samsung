# Разработка, обновление и отладка

Первую установку SDK, подключение телевизора и создание собственных сертификатов
пройдите по [README](../README.md#самостоятельная-установка).
Здесь описан повседневный цикл после этой подготовки. Команды проверены на Linux
с Bash. Само приложение работает напрямую с сервисом и AVPlay; компьютер нужен
только для разработки и установки.

## Структура проекта

| Файл | Ответственность |
|---|---|
| `app/api.js` | Авторизация, каталоги, статусы, ссылки серий, выбор и проверка HLS фильмов |
| `app/main.js` | Экраны, сортировка, страницы, поиск и фокус пульта |
| `app/player.js` | AVPlay, HTML5 fallback, кнопки, жизненный цикл воспроизведения |
| `app/styles.css`, `app/index.html` | Оформление и структура интерфейса |
| `app/config.xml` | Версия, идентификаторы, минимальный Tizen и разрешения |
| `app/icon.svg`, `app/icon.png` | Исходник и квадратная PNG-иконка Smart Hub |
| `tests/` | Проверки API и поведения плеера с тестовыми данными |
| `tools/package.py` | Проверки ресурсов, сборка и подпись `.wgt` |
| `tools/preview.py` | Локальный браузерный preview |
| `tools/certificates.py` | Необязательная личная резервная копия подписи |

Проверенное устройство — Samsung QE55Q70TAUXRU, Tizen 5.5, ARMv7,
Chromium 69. Сохраняйте совместимый JavaScript: обычные функции, `var`, Promise;
не добавляйте синтаксис и Web API только потому, что они работают в новом Chrome.
У приложения нет внешних JS-зависимостей и стадии транспиляции.

## Подготовить изменения

Для собственного форка и PR используйте процесс из [CONTRIBUTING](../CONTRIBUTING.md).
Из чистой рабочей копии создайте ветку, затем меняйте исходники:

```sh
git switch -c feature/my-change
npm test
npm run build
npm run preview
```

`npm test` проверяет поведение API и плеера на синтетических данных: аккаунт,
сеть и SDK не нужны. `npm run build` проверяет XML, синтаксис JS и совпадение
версий, затем создаёт `.local/Soap4Samsung-unsigned.wgt`.
Без подписи этот пакет не предназначен для установки на ТВ.
Если добавляете новый JS-файл, изображение или другой ресурс приложения,
внесите его в `PUBLIC_FILES` в `tools/package.py`: сборщик использует явный список
и не копирует посторонние файлы из `app/`.

Preview открывается на `http://127.0.0.1:8765`, слушает только loopback
и читает исходники из `app/`. Вход выполняется через экран приложения;
учётные данные не нужны ни в `.env`, ни в `app/config.local.js`.
HTML5-видео в браузере не заменяет AVPlay: HLS фильмов и особенности ТВ проверяйте
на устройстве. Для изменения текста не нужны новые тесты, повторяющие сам текст;
для изменения поведения добавляйте проверки ошибки, результата или гонки.

В [`.env.example`](../.env.example) показаны только параметры локального окружения:
путь SDK, IP своего ТВ и имя своего профиля. Можно скопировать его в игнорируемый
`.env`, исправить значения и загрузить в текущий Bash:

```sh
set -a
. ./.env
set +a
```

Сам по себе файл не читается приложением и не входит в пакет. Не добавляйте
в него логин/пароль Soap4me, ключи и токены. Команды ниже используют загруженные
значения; без `.env` подставляются примеры, которые нужно заменить своими.

## Правила поведения, которые нужно сохранить

Постоянные требования находятся в [AGENTS.md](../AGENTS.md).
Важные для разработки зависимости:

- Статусы просмотренного приходят с сервиса. Кнопки отметки сериала/сезона меняют
  аккаунт и обновляют счётчики. Окончание видео само по себе статусы не меняет.
- Автопереход действует только после естественного конца серии и только в том же
  сезоне. Конец сезона возвращает список, конец фильма — его карточку.
  Back, ошибка и Home не запускают следующее видео.
- Качество серий выбирается среди русских вариантов (`translate=4`):
  4K → Full HD → 720p → SD.
- Для фильма свежая страница сайта используется только для извлечения конфигурации
  плеера; HTML и скрипты сайта не исполняются. Исходный HLS master нужен для выбора
  AVC/H.264 до 4K и русской аудиогруппы. Из child URI строится фильтрованный CDN
  master с нужным видео и русским звуком без субтитров, ответ проверяется повторно.
- Директория child URI может отличаться от исходного master. Сохраняются проверка
  origin, директории и query, выбранных файлов, разрешения и отсутствия субтитров.
  API-токен и cookies не передаются CDN. Fallback к исходному master не допускается:
  именно такой поток вызывал закрытие процесса на проверенном ТВ.
- Перед `prepareAsync()` фиксируется выбранный битрейт через `ADAPTIVE_INFO`.
  При свободном выборе смешанного AVC/HEVC master наблюдались неверный вариант
  и зависание перемотки. Подробности схемы и границ проверки — в [API.md](API.md).
- Пока `seekTo` не завершился через success/error callback, остальные вызовы
  AVPlay откладываются. Сохраняйте очередь паузы/остановки/нового запуска
  и защиту от callbacks предыдущего воспроизведения.
- Индикатор качества использует фактическое разрешение декодера. Успешное чтение
  кэшируется для текущего запуска, во время seek не выполняется. Панель скрывается
  через CSS opacity за 220 мс; пауза оставляет её видимой. Новые циклы опроса не нужны.
- Сортировка фильмов работает на уже загруженном каталоге и сохраняется локально.
  Не добавляйте запросы при каждом переключении или избыточную перерисовку карточек.

## Версия и иконка

Номер выпуска меняется одновременно в `package.json` и атрибуте `version`
в `app/config.xml`. `required_version="5.5"` — минимальная версия платформы,
её не надо менять вместе с версией приложения. Сборщик генерирует
`config.local.js` только с публичным номером версии; исходный локальный файл
исключается из пакета.

App ID `Soap4TV001.Soap4Samsung` и package ID `Soap4TV001` сохраняются при обычном
обновлении. Для установки новых версий на свой ТВ сохраняйте свой author certificate.
Профиль `Soap4Samsung` — рекомендуемое локальное имя, а не общая подпись проекта.

Smart Hub использует `app/icon.png` размером 117×117. При изменении исходника
`app/icon.svg` экспортируйте соответствующий квадратный PNG в том же размере
и включите оба файла в изменение. Сборщик не преобразует SVG автоматически.
Используйте имеющийся SVG-редактор/экспортёр, затем проверьте размер и отсутствие
непреднамеренной прозрачной рамки или скруглений.

## Подписать и обновить свой телевизор

Значения ниже — примеры: замените путь SDK, адрес ТВ и имя устройства своими.
Имя для `soap_target` берётся из вывода `sdb devices`.

```sh
soap_sdk="${TIZEN_STUDIO_PATH:-$HOME/tizen-studio}"
soap_tv_ip="${TV_IP:-192.168.1.20}"
soap_profile="${TIZEN_PROFILE:-Soap4Samsung}"
soap_tv="$soap_tv_ip:26101"
soap_sdb="$soap_sdk/tools/sdb"
soap_tizen="$soap_sdk/tools/ide/bin/tizen"

"$soap_sdb" connect "$soap_tv"
"$soap_sdb" devices
soap_target="ИМЯ_УСТРОЙСТВА_ИЗ_SDB_DEVICES"
```

После проверки исходников последовательно выполните:

```sh
npm test
npm run build
python3 tools/package.py --profile "$soap_profile" --tizen "$soap_tizen"
"$soap_sdb" -s "$soap_tv" shell 0 was_kill Soap4TV001.Soap4Samsung
"$soap_tizen" install -n Soap4Samsung.wgt -t "$soap_target" -- .local
"$soap_tizen" run -p Soap4TV001.Soap4Samsung -t "$soap_target"
```

Дождитесь результата каждой команды. Если процесс уже завершён, сообщение
`was_kill` об отсутствии процесса допустимо. Ошибка подписи или установки
требует исправления до следующего шага. Не используйте `uninstall` при обычном
обновлении: установка поверх с прежним author сохраняет данные приложения.

Сборщик также может найти Tizen CLI по переменной `TIZEN_STUDIO_PATH`, через `PATH`
или в `~/tizen-studio`; явный `--tizen` помогает исключить путаницу нескольких SDK.
Сертификаты и их пароли остаются под управлением локального Certificate Manager.
Перенос подписи описан в [CERTIFICATES.md](CERTIFICATES.md).

После установки проверьте номер версии и изменённый экран. Для изменений плеера
проверьте русское аудио, фактическое разрешение, паузу, перемотку, продолжение
и Back с возвратом фокуса. При изменении автоперехода нужны естественный конец,
последняя серия и отсутствие следующего видео после Back/ошибки/Home.
Для фильмов проверьте также возврат к той же карточке после конца.

Не запускайте массовые отметки на чужом аккаунте ради тестирования.
На собственном аккаунте учитывайте, что они действительно меняют серверные статусы.

## Отладка AVPlay и интерфейса на ТВ

Для запуска отладки сначала завершите обычный процесс:

```sh
"$soap_sdb" -s "$soap_tv" shell 0 was_kill Soap4TV001.Soap4Samsung
"$soap_sdb" -s "$soap_tv" shell 0 debug Soap4TV001.Soap4Samsung
```

Возьмите номер порта из ответа: он может меняться между запусками.
Запуск debug поверх уже работающего процесса на проверенном ТВ зависал.
Если прямое подключение к этому порту недоступно, пробросьте его через SDB,
подставив фактическое число в `soap_debug_port`:

```sh
soap_debug_port="ПОРТ_ИЗ_ОТВЕТА_DEBUG"
"$soap_sdb" -s "$soap_tv" forward tcp:9223 "tcp:$soap_debug_port"
```

Откройте `http://127.0.0.1:9223/json` и подключитесь к page WebSocket приложения
из `webSocketDebuggerUrl`; при необходимости замените его host/port на
`127.0.0.1:9223`. Старому Chromium могут требоваться совместимые инструменты
Web Inspector. Современный `connectOverCDP` не гарантирует совместимость
с его Browser/Target API. Официальный вариант — запуск Debug As →
Tizen Web Application из IDE и
[Samsung Web Inspector](https://developer.samsung.com/smarttv/develop/getting-started/using-sdk/web-inspector.html).

Для безопасной диагностики через `Runtime.evaluate` с `returnByValue: true`
достаточно небольшого объекта состояния:

```js
({
  ready: document.readyState,
  section: document.getElementById('section-title').textContent,
  shows: document.querySelectorAll('.show-card').length,
  episodes: document.querySelectorAll('.episode-button').length,
  playerVisible: !document.getElementById('player-view').hidden,
  playbackState: document.getElementById('player-state').textContent
})
```

Состояние воспроизведения проверяется через `webapis.avplay.getState()` и рост
`getCurrentTime()`. Не вызывайте их или другие методы AVPlay во время незавершённого
`seekTo`. Для изменения состояния используйте штатные обработчики кнопок.

На проверенном ТВ `Page.captureScreenshot` через CDP зависал. Используйте DOM
и состояние плеера, а изображение/звук проверяйте на самом экране.
Не публикуйте полный localStorage, заголовки запросов или ответы авторизации.
AVPlay загружает видео вне обычной сетевой панели страницы; отсутствие потока
в Network не означает отсутствие запроса. На розничных ТВ системные crash logs
и `sdb dlog` недоступны согласно
[Samsung Application Testing FAQ](https://developer.samsung.com/smarttv/develop/faq/application-testing.html).

После отладки верните обычный запуск и удалите только свой проброс порта:

```sh
"$soap_sdb" -s "$soap_tv" shell 0 was_kill Soap4TV001.Soap4Samsung
"$soap_tizen" run -p Soap4TV001.Soap4Samsung -t "$soap_target"
"$soap_sdb" -s "$soap_tv" forward --remove tcp:9223
```

Команды запуска также используются в
[Samsung/Wits](https://github.com/Samsung/Wits/blob/master/lib/appLaunchHelper.js).

## Перед публикацией изменения

Проверьте `git status --short`, `git diff` и `git diff --cached`.
В коммит входят исходники, тесты, документация и публичные примеры.
`.local/`, `.env`, SDK/workspace, `.wgt`, приватные конфигурации, cookies,
сессии, сертификаты и любые архивы подписи остаются локальными.
Исключения в `.gitignore` не заменяют просмотр diff.

В PR опишите результат, проверки и ограничения. Если реального ТВ не было,
так и напишите: прохождение тестов с AVPlay-заглушкой не доказывает работу декодера.
Публикуйте только обезличенные ошибки и минимальные синтетические примеры.
Процесс принятия изменений: [CONTRIBUTING.md](../CONTRIBUTING.md).
