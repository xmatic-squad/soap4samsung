# API Soap4me: результаты проверки

Дата: 2026-09-10. Основа исследования:
[Soap4me/Kodi/addon.py](https://github.com/Soap4me/Kodi/blob/master/addon.py).
Это описание наблюдаемого API и протокола существующего клиента, а не гарантия
стабильности публичного API со стороны сервиса.
Поля рейтингов и года дополнительно проверены 2026-09-17: каталог сериалов
через `GET /soap/`, каталог фильмов через `GET /movies/` на телевизоре.

## Адрес API и проверка на телевизоре

Базовый адрес приложения и локального preview: `https://api.soap4youand.me/v2`.
Это API зеркала [soap4youand.me](https://soap4youand.me/).
Анонимный `GET /auth/check/` на этом API возвращает HTTP 200 и признаки отсутствия
авторизации. Пути `/v2/` и `/api/v2/` на самом домене `soap4youand.me` для API не подходят.

Исходный адрес из Kodi — `https://api.soap4.me/v2`. С компьютера он отвечал нормально.
На Samsung с Tizen 5.5 вход и `/auth/check/` через этот адрес проходили,
но загрузка `/soap/my/` останавливалась примерно после 68 КБ и завершалась таймаутом.
После переключения на `api.soap4youand.me` прямой вход и получение списка «Мои»
на телевизоре сработали. Причина остановки передачи
через исходный домен отдельно не установлена.

Для проверенного входа и списка моих сериалов упакованное приложение обращается
к зеркалу напрямую, без локального API-посредника. Доступ из обычного браузера
проверяется отдельно через локальный preview.

## Авторизация

`POST /auth/`, тело `application/x-www-form-urlencoded` с полями `login`, `password`.
При успехе JSON содержит `ok: 1` и `token`. Последующие запросы используют заголовок
`X-API-TOKEN`. Также обязательны cookies: с сохранённой cookie jar проверка
авторизации возвращает 1, с тем же токеном без cookies — 0. XHR в приложении
использует `withCredentials=true`.

Cookie привязана к домену. Сессия, полученная на `api.soap4.me`, не заменяет вход
на зеркале: после смены адреса нужно авторизоваться на новом хосте. Это относится
и к preview: в нём нужно войти через экран приложения. Его cookies хранятся
в памяти локального сервера, личные сессии из файлов не загружаются.

Проверка авторизации: `GET /auth/check/`, наблюдались `logged: 1` и `loged: 1`.
Не журналировать токены, cookies, пароли и полный ответ авторизации.

## Каталог

| Запрос | Содержание | Статус проверки |
|---|---|---|
| `GET /soap/my/` | Мои сериалы | Успех; список сериалов аккаунта |
| `GET /episodes/continue/` | Продолжить просмотр | Успех; список серий |
| `GET /episodes/new/my/` | Новые серии моих сериалов | Успех; список серий |
| `GET /soap/` | Полный каталог | Успех; список сериалов |
| `GET /episodes/{sid}/` | Серии сериала | Успех; объект с полями `episodes`, `covers` |
| `GET /movies/` | Каталог фильмов | Успех; список фильмов |

Сериал содержит `sid`, `title`, `title_ru`, описание, обложки, жанры, рейтинги,
`watching`, `unwatched` и другие поля. Часть чисел передаётся строками.

Поля для отображения рейтингов и сортировки уже входят в каталоги сериалов
и фильмов; дополнительные запросы к IMDb, Кинопоиску или страницам сайта не нужны:

| Данные | Поля API | Использование |
|---|---|---|
| IMDb | `imdb_rating`, `imdb_votes` | Значок IMDb и сортировка по оценке |
| Кинопоиск | `kinopoisk_rating`, `kinopoisk_votes` | Значок КП и сортировка по оценке |
| Soap4me | `soap_rating`, `soap_votes` | Значок Soap и сортировка по оценке |
| Год выхода | `year` | Новые по году первыми |

В проверенном каталоге сериалов оценки и число голосов — строки, в каталоге
фильмов оценки — числа; `year` приходит строкой. Нулевая, отсутствующая или
неверная оценка не отображается и при сортировке идёт после известных значений.
Допустимы только конечные оценки выше 0 до 10. Значок округляется до десятых,
при сортировке сохраняется точность ответа. Голоса доступны в API, но в интерфейсе
пока не выводятся.

На сайте [сортировка «рейтинг»](https://soap4youand.me/) использует IMDb;
«смотрят» относится к числу пользователей (`likes`), а не к `soap_rating`.
У сериалов также есть `updated` — Unix timestamp или `null`; это отдельное
поле, не год выхода. В приложении доступны только сортировки по названию,
году и трём оценкам, а в «Моих» — также по `unwatched`.
Они выполняются локально на загруженном каталоге без повторного GET.

Поиск использует слова из `title_ru`, `title`, `title_original`, `soap_ru`, `soap`,
если соответствующие поля присутствуют. Регистр, лишние пробелы и различие ё/е
не учитываются; все слова запроса должны встретиться среди названий.

В списках новых серий элементы содержат `sid`, `season`, `episode`, названия и `files`.
Ответ `/episodes/{sid}/` содержит плоский массив `episodes`; его элементы не содержат
`sid`, поэтому для запуска нужно сохранить идентификатор выбранного сериала.
Поле `covers` этого ответа — массив `{season, small, big}`. Обложки сериалов в каталоге
имеют вид `{small, big}`. Каждый вариант файла содержит `eid`, `hash`, `quality`, `translate`.

Соответствия из Kodi:

- `quality`: 1 — SD, 2 — 720p, 3 — FullHD, 4 — 4K.
- `translate`: 1 — оригинал, 2 — оригинальные субтитры, 3 — русские субтитры,
  4 — перевод. Реальный состав дорожек нужно проверять в каждом варианте.

Приложение выбирает максимальное доступное качество с `translate=4`:
4K → FullHD → 720p → SD. Варианты без `eid` или `hash` не участвуют в выборе.

## Получение потока

Для выбранного варианта файла:

1. Получить `sid` выбранного сериала, `eid` и исходный `hash` из варианта файла.
2. Вычислить MD5 от UTF-8 строки, составленной без разделителей:
   `token + eid + sid + исходный_hash`.
3. Выполнить `POST /play/episode/{eid}/` с формой `eid` и `hash`,
   где `hash` — вычисленный MD5 в шестнадцатеричном виде.

Проверенный ответ содержит `ok`, `stream`, `subs`, `start_from`, `poster`, `title`.
Получение ссылки успешно и для FullHD-варианта с русскими субтитрами. В этом ответе
`subs` — объект с признаками `available`, `ru`, `en` и полями сервиса Intersub;
это не список готовых URL субтитров. Их фактическую передачу плееру нужно исследовать.
Полученный `stream` доступен с хоста `storage2.soap4youand.me`.
Полные ссылки не включены в документ, поскольку содержат данные доступа.

Проверенный вариант FullHD:

- Контейнер MP4, видео H.264, 1920×803, 24000/1001 кадров/с.
- Звук AAC, 48 кГц, 2 канала.
- Длительность 3619 секунд, размер файла около 1.85 ГБ.
- `Range: bytes=0-65535` вернул `206 Partial Content` и корректный `Content-Range`.
- Запрос к файлу выполнился без `X-API-TOKEN` и cookies.
- `moov` расположен сразу после `ftyp`, размер метаданных около 2.16 МБ.

Характеристики этого файла получены при первоначальной проверке с компьютера.
Они не гарантируют такой же формат для всех серий. Срок жизни URL и привязка к IP
отдельно не установлены; приложение получает свежую ссылку перед каждым запуском.

На окончательном установленном пакете 0.3.1 первая серия «Во все тяжкие»
(`sid=34`, сезон 1, серия 1) прошла 60 секунд и оставалась в `PLAYING`.
AVPlay подтвердил H.264 3840×2160 и AUDIO `rus`. Индикатор показывал 4K,
панель скрывалась; перемотка на 10 секунд завершилась, позиция продолжила
расти до 1:17. Back вернул фокус на `episode-1-1`.

На проверенных API-ответах с `Origin: http://localhost` заголовок
`Access-Control-Allow-Origin` отсутствовал. Прямой доступ из обычной локальной
web-страницы нельзя считать подтверждённым. Упакованное Tizen-приложение с сетевыми
разрешениями успешно выполнило прямые вход и запрос моих сериалов на зеркале;
это не означает, что обычная браузерная страница получит такие же разрешения.

## Фильмы

`GET /movies/` возвращает массив фильмов. Идентификатор называется `id`, не `sid`
и не `mid`. Среди полей есть `title`, `title_ru`, `title_original`, `year`, `runtime`,
`countries`, `qualities`, `watched`, `liked`, рейтинги и `covers: {small, big}`.
Поля рейтингов совпадают с каталогом сериалов и перечислены выше.
Каталог содержит достаточно информации для карточки фильма; отдельный запрос
страницы выполняется только при нажатии «Смотреть».

В официальном Kodi-клиенте нет реализации фильмов. Отдельный REST-метод деталей
и запуска фильма не найден. Приложение использует обычную авторизованную страницу
фильма на зеркале:

1. После успешного входа в API выполнить `POST https://soap4youand.me/login/`
   с формой `login`, `password`. У проверенной формы сайта нет дополнительных
   скрытых полей. Это создаёт отдельную cookie сайта; пароль не сохраняется.
2. При запуске фильма получить `GET https://soap4youand.me/movies/{id}/` с cookie.
3. В блоке `cache["movie_player_ID"] = new Playerjs({...})` прочитать JSON-строку
   свойства `file`: она содержит свежий URL HLS master-плейлиста.
4. Загрузить master без `X-API-TOKEN` и cookie. Убедиться, что это `#EXTM3U` и
   в `#EXT-X-MEDIA` есть русская дорожка `TYPE=AUDIO`. Русские субтитры не считаются
   русской озвучкой.
5. Среди `#EXT-X-STREAM-INF` выбрать AVC/H.264 (`avc1` или `avc3`) с `AUDIO`,
   указывающим на группу с русской дорожкой. Предпочитать наибольшее число пикселей
   при ширине не более 3840 и высоте не более 2160; при одинаковом числе пикселей —
   больший `BANDWIDTH`. Приоритет качества: 4K → FullHD → 720p → SD.
   Наличие русского звука без совместимой
   видеоверсии само по себе недостаточно для запуска.
6. Из URI выбранного видео `index-fN-vN.m3u8` и русской аудиодорожки
   `index-fN-aN.m3u8` построить в их общей директории
   `master-{videoSelector}-{audioSelector}.m3u8`. Например,
   `index-f5-v1.m3u8` и `index-f1-a1.m3u8` дают `master-f5-v1-f1-a1.m3u8`.
   Индексы строго положительные. Оба URI должны использовать HTTPS и тот же CDN
   origin, одинаковую директорию и query. Директория может находиться вне `/hls/`
   и отличаться от адреса исходного master; меняется только имя файла,
   подписанный путь и query сохраняются.
7. Загрузить новый master без токена и cookies. Требовать ровно один AVC-вариант
   с выбранным разрешением и прежними селекторами видео/аудио, одну русскую
   аудиодорожку, отсутствие `SUBTITLES` и корректные child URI. При ошибке
   не возвращаться к исходному master.
8. Передать системному плееру URL проверенного фильтрованного master
   и `hlsBitrate` из его единственного `BANDWIDTH`.
   Положение старта — 0; отметка просмотра
   и сохранение позиции фильма автоматически не отправляются.

Селекторы файлов и дорожек описаны в
[nginx-vod: Filename structure](https://github.com/kaltura/nginx-vod-module#filename-structure).
Их поддержка дополнительно проверена на CDN сервиса. Фильтрованный master
сохраняет отдельный русский звук, исключая ненужные видео и субтитры.
Он обслуживается самим CDN; файловая система ТВ и посредник на компьютере
в получении или воспроизведении этого потока не участвуют.

HTML и JavaScript сайта не исполняются; `eval` и загрузка скриптов сайта не нужны.
Парсер ограничен блоком с конкретным числовым идентификатором фильма. Принимаются
со страницы только HTTPS-ссылки вида `https://cdn-*.soap4youand.me/hls/.../master.m3u8`, без
пользовательской части URL и фрагмента. Полные действующие ссылки не журналируются.
Это ограничение `/hls/` относится к исходному URL со страницы; адреса child
и фильтрованного master проверяются отдельно по правилам выше.
Это интеграция с наблюдаемой разметкой сайта: при изменении формата клиент должен
сообщить об ошибке, а не пытаться исполнить содержимое страницы.

API-cookie ограничена хостом API и не авторизует сайт. Один `X-API-TOKEN` тоже
не даёт доступа к странице фильма. Неавторизованный запрос может перенаправляться
на главную с HTTP 200: отсутствие плеера и формы `/logout` означает
`SITE_AUTH_REQUIRED`, и интерфейс предлагает повторный вход. Ошибка дополнительного
входа на сайт не отменяет успешный вход в API, поэтому сериалы остаются доступны.

Некоторые исходные master-плейлисты содержат 4K, AVC, HEVC, несколько аудиодорожек
и субтитры. Исходный master используется для анализа и не передаётся AVPlay.
Флаги `DEFAULT` и `AUTOSELECT` не заменяют проверку русского языка: в проверенном
фильтрованном ответе единственная русская дорожка имела оба флага `NO`.

Для выбранного битрейта `B` AVPlay получает
`ADAPTIVE_INFO = BITRATES=(B-100)~(B+100)|STARTBITRATE=B` после `open()` и до
`prepareAsync()`: выражения здесь обозначают вычисленные числовые значения.
Это ограничивает выбор плеера небольшим диапазоном вокруг выбранного AVC-варианта
в фильтрованном master с русским звуком. Samsung документирует диапазон `BITRATES`
и числовой `STARTBITRATE` в состоянии `IDLE` в
[руководстве по адаптивным потокам](https://developer.samsung.com/smarttv/develop/guides/multimedia/adaptive-streaming.html).

На целевом ТВ автоматический выбор HEVC из смешанного master ранее приводил
к зависанию перемотки, поэтому выбор ограничен AVC. Для «Анчартед» (`id=457`)
исходный master дважды завершал процесс приложения примерно на 45-й секунде;
отключение принудительного выбора аудио не помогло. Контрольный master, из
которого исключены только два файла субтитров, сохранил 6 видеоверсий,
2 аудиодорожки и выбранный `BANDWIDTH=8242044`; воспроизведение достигло
428229 мс (более 7 минут), список дорожек содержал VIDEO и AUDIO без TEXT.

В ходе проверок установленного 0.3.1 `getMoviePlayback` на самом ТВ получил
и проверил выбранные master, после чего AVPlay подтвердил:

- «Анчартед», фильм 457: `master-f5-v1-f1-a1.m3u8`, `BANDWIDTH=8242044`,
  AVC 1920×804. После 150 секунд проверки — `PLAYING`, позиция 147862 мс.
- «1+1», фильм 12: `master-f7-v1-f1-a1.m3u8`, `BANDWIDTH=15661190`,
  AVC 4K 3840×2080. После 121 секунды проверки — `PLAYING`, позиция 118827 мс.

Оба выбранных потока содержали русскую аудиодорожку и не содержали TEXT.
На «Анчартед» пауза сохраняла видимую панель более 5 секунд, продолжение
возвращало её автоскрытие; `seek +10` завершился успешно (3:25 → 3:41 после
6 секунд), Back вернул фокус на `movie-play`. У обоих фильмов подтверждено
исчезновение панели с индикатором фактического качества (`opacity` 1 → 0).
У «1+1» перемотка к последним 15 секундам завершилась естественным концом:
плеер скрылся, осталась карточка того же фильма с фокусом на `movie-play`.

При отсутствии русской
аудиогруппы возвращается `NO_RUSSIAN_AUDIO`, при отсутствии подходящего AVC-варианта —
`NO_COMPATIBLE_VIDEO`; сообщения не содержат URL потока.

В локальном preview используются только `POST /site/login/` и
`GET /site/movies/{id}/`; посредник направляет их на фиксированный хост зеркала
и не передаёт сайту API-токен. HLS-плейлист доступен напрямую, с
`Access-Control-Allow-Origin: *`. Обычный Chrome с HTML5-видео в preview не
воспроизводит такой HLS самостоятельно; воспроизведение проверяется через AVPlay
на телевизоре. Компьютер не участвует в просмотре через установленное приложение.

## Прогресс просмотра

В Kodi найден `POST /play/episode/{eid}/savets/` с полями `eid`, `time` в секундах.
Автоматическое сохранение позиции в этой версии не добавлено.

## Массовая отметка просмотренного

Протокол подтверждён исходниками официального Kodi-клиента (`WATCHING_URL`,
`mark_watched`, `SoapHttpClient._request`):

| Действие | Запрос | Поля формы |
|---|---|---|
| Весь сериал просмотрен | `POST /episodes/watch/full/{sid}/` | `sid` |
| Сезон просмотрен | `POST /episodes/watch/full/{sid}/{season}/` | `sid`, `season` |

Используются обычные `X-API-TOKEN` и cookie сессии, форма
`application/x-www-form-urlencoded`. Дополнительная MD5-подпись не нужна.
Успех требует явного `ok: 1` в JSON; HTTP 200 без этого признака недостаточно.
Сезон `0` допустим для спецвыпусков. Клиент возвращает исходный подтверждённый ответ;
после успеха интерфейс должен перечитать серии и обновить список моих сериалов.

`/soap/watch/{sid}/` имеет другое назначение — добавление сериала в «Мои».
Для отметки уже просмотренных серий этот метод не используется.
При проверке повторной отметки уже просмотренного материала сервер возвращал
`ok: 1`, повторное чтение сохраняло прежние статусы. Контракт, обработка
ошибок и допустимость сезона `0` также проверены модульными тестами.

## Независимая реализация

Soap4Samsung реализует протокол отдельно от Kodi и использует AVPlay на телевизоре.
Устанавливать Kodi-плагин на ТВ не требуется. Код плагина имеет лицензию LGPL-3.0;
при заимствовании его кода нужно соблюдать её условия. Наша реализация протокола
и MD5 написана самостоятельно; лицензия проекта указана в [LICENSE](../LICENSE).
